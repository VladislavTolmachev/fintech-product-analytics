# Data Dictionary

All records are synthetic and reproducibly generated by `generate_synthetic_data.py`. Timestamp columns use PostgreSQL `TIMESTAMP` for this initial local project; timezone assumptions will be documented during data generation.

## `users`
| Column | Type | Meaning |
|---|---|---|
| `user_id` | BIGINT | Primary key |
| `signup_at` | TIMESTAMP | Registration timestamp |
| `acquisition_channel` | VARCHAR(50) | Acquisition source |
| `country_code` | CHAR(2) | Country code; defaults to `MX` for the fictional case |

## `card_applications`
| Column | Type | Meaning |
|---|---|---|
| `application_id` | BIGINT | Primary key |
| `user_id` | BIGINT | Applicant; references `users` |
| `submitted_at` | TIMESTAMP | Application submission timestamp |
| `decision_at` | TIMESTAMP, nullable | Final decision timestamp |
| `application_status` | VARCHAR(20) | `pending`, `approved`, or `rejected` |

A user may submit multiple applications. Pending applications have no decision timestamp.

## `cards`
| Column | Type | Meaning |
|---|---|---|
| `card_id` | BIGINT | Primary key |
| `application_id` | BIGINT | Approved application associated with the issued card; unique in this model |
| `issued_at` | TIMESTAMP | Card issuance timestamp |
| `activated_at` | TIMESTAMP, nullable | Activation timestamp |
| `card_status` | VARCHAR(20) | `issued`, `active`, `blocked`, or `closed` |

## `transactions`
| Column | Type | Meaning |
|---|---|---|
| `transaction_id` | BIGINT | Primary key |
| `card_id` | BIGINT | Card associated with the transaction |
| `transaction_at` | TIMESTAMP | Transaction timestamp |
| `amount` | NUMERIC(12,2) | Positive transaction amount |
| `transaction_type` | VARCHAR(20) | `purchase`, `refund`, or `cash_withdrawal` |
| `transaction_status` | VARCHAR(20) | `completed`, `declined`, or `reversed` |

For the initial activation analysis, a successful first purchase means `transaction_type = 'purchase'` and `transaction_status = 'completed'`. Net spend and refund treatment require separate definitions.

## `user_events`
| Column | Type | Meaning |
|---|---|---|
| `event_id` | BIGINT | Primary key |
| `user_id` | BIGINT | User who triggered the event |
| `event_time` | TIMESTAMP | Event timestamp |
| `event_name` | VARCHAR(50) | Event name |
| `session_id` | VARCHAR(100), nullable | Session identifier |

The event taxonomy will be defined during synthetic-data generation.

## Synthetic data snapshot
The generator creates 5,000 users, application records (including repeat applications), issued cards, transactions, and in-app events. Signup dates range from January 2025 through June 2026; activity data runs through September 2026 so the cohort analysis has follow-up time. The exact row counts are printed by the generator and should be rechecked after regeneration.

Event taxonomy: `app_open`, `home_view`, `card_screen_view`, `transaction_history_view`, `profile_view`, `payment_attempt`, and `settings_view`. A tracked event is treated as evidence of in-app activity; this is a simplifying synthetic-data assumption, not a claim about a real product's analytics instrumentation.
